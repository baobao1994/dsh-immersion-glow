# 已知限制

按影响面排序。每条都写清「会看到什么」与「为什么不修」，避免使用者把设计当成 bug。

---

## 计时相关

**空闲 3 分钟后计时停住**
沉浸时长 = **活跃时长**，不是「页面开着多久」。鼠标键盘都停 3 分钟后就不再累加，
直到下次操作。代价是「挂机看代码」这种场景不会被计入。

**隐藏标签页超过 10 分钟再回来，当前时段归零**
浏览器会节流甚至冻结后台标签页的定时器，隐藏期间的时长无法可信计算。
我们选择的策略是**冻结 + 切回后按间隔判新时段**，绝不反向补算 —— 宁可少算，不多算。
隐藏 ≤ 10 分钟则续算。

**多标签共用一份计时**
`activeMs` 取各标签中的较大值，不会重复累加，但也不是精确合并。
两个标签同时活跃时，计时会比真实值略小。

**跨零点只重置「今日」统计，不清当前时段**
凌晨 0 点还在写代码时，你不会突然看到计时归零。

## 指标相关

**对话轮次 / 工具调用只统计「已加载窗口」**
DSH 的会话是分页加载的。向上还没翻到更早的历史时，计数偏低。
出现这种情况时记录卡会显示「仅统计当前窗口内的数据」，**看到这行说明口径已生效**，不是 bug。

**首条消息的第一句会被读取（截断到 60 字），用作任务名**
这是 v4 相对旧版**唯一放宽的隐私边界**。旧承诺是「绝不触碰正文」；要拿到能认出这次任务的
名字，只能读第一行。范围严格限定：只取首条 user 消息、只取 text part、只留 60 字。
不读后续提问、不读模型输出、不读工具参数。若你不要这个功能，最直接的应对是不要收藏那些记录。

**模型归属在 trajectory 投影不可用时是近似值**
宿主没有提供「按模型拆分耗时」的投影，所以这份数据由 chat 快照推导（每个 assistant 节点按
`completedTime - stepStartTime` 计时，再经 `trajectory` 的 `providerMetadata` 归到模型）。
`trajectory` 拿不到时退回「当前模型」—— 一个会话中途切过模型的话，这个归属是错的，
但界面上标为近似。要完全准确的前提是宿主提供对应投影。

**被中断的模型调用不计入耗时**
被取消 / 失败的步骤在快照里没有 `completedTime`，因此不计时长。这是刻意的：宁可少算，
也不用猜一个结束时刻。

注意界面上**不会**单独显示「中断耗时」这一栏。早先版本曾引用过一个 `cancelledMs` 字段，
但它从来没有任何生产者（`undefined > 0` 恒为 false），是一段永远不会出现的死代码；
在确认无法诚实产出该数据后已删除。现在每个模型只显示确实测得到的：净耗时、轮次、调用次数。

**「哪个模型得心应手」不会自动给结论**
我们只有耗时、首字延迟、解码速度、轮次 —— 全是客观量，**没有任何质量信号**。
所以汇总只把证据和你的自评并排放，不做判断。让脚本从耗时反推「擅长什么」是伪科学。

**无会话时显示的是上一次会话的统计**
首页/欢迎页没有当前会话，探针不挂载。此时记录卡明确标注「无打开会话」，
不会把旧数据冒充成新数据。

## 视觉相关

**白天时段的记录没有「晨间 / 深夜」标签**
只有 `[5,10)` 与 `[22,5)` 会打时间标签。多数会话发生在白天，给每个人发「白天」
等于没有信息量。长度标签（长跑 / 碎片）不受此影响。

**提醒卡到点只留一次未读，刷新即清**
未读状态只保当前页面生命周期：刷新、切标签页后徽标不再出现。
已点开过的提醒不会再次变未读。这是为了不让你回到页面时被旧提醒追着跑。

**短时段不产生收藏候选**
自动入库门槛是 5 分钟。手动收藏则要求 ≥ 1 分钟（按钮否则禁用）。

## 能力边界

**MVP 不含**：视觉变体解锁（F8）、会话静默补记（F9）、意图锚定（F10–F12）、
「锚定」强度档、toast 提醒模式、可配置动画参数、数据迁移脚本。

**画廊上限 50 条**，超出丢最旧的。没有「导出为文件」，只有「复制统计 JSON」到剪贴板。

**清除本插件数据后需要刷新**
已渲染的组件持有旧快照。下一次 tick 会自然对齐，但刷新更干净。

## 环境相关

**装完必须重启 DSH，刷新页面无效**
新增 bundle 属结构性变更，`patchReload: live` 只覆盖配置热更。

**`link:` 安装的插件，源目录挪走会静默失效**
profile 存的是绝对路径。移动后需用新路径重装：
```sh
D="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
"$D" plugin --profile desktop remove dsh-immersion-glow
"$D" plugin --profile desktop add "/新/的/绝对/路径"
```

**版本对齐的是 DSH `0.2.0-rc.2` / cordis `4.0.4`**
PRD v0.2 里写的 `0.1.0-rc.6` 与实际安装版本不符（预发布版本元组不同，`^0.1.0-rc.6`
不匹配 `0.1.1-rc.2`），所以 `peerDependencies` 按实际版本声明，且都设为 `optional`。
DSH 升级后若插槽契约变化，需要重新核验 —— 详见 [ADR.md](ADR.md)。

## 与 PRD v0.2 的偏离

三处实现级修正（不改产品行为，但不改就装不上）：

1. **不用 slot 的 `store:` 座**，改 `provideRoot` —— 否则同一个 handle 跨 root/session
   两个 scope，注册时直接抛错（ADR-101）。
2. **`dsh.client.inject` 留空**、`cordis inject` 只留 `slots` —— 可选服务写进 inject
   会让 fiber 卡 pending 并拖垮整个前端（ADR-102）。
3. **不 require `ui-primitives`**，剪贴板与标签自绘 —— 官方插件守则明令禁止（ADR-110）。

两处范围微调：

4. **页面隐藏冻结计时**放进 MVP（原在 V1.1）—— 明知失真还累计不合理（ADR-107）。
5. **设置行不传 `label`** —— 该插槽没有任何 label 投影点，传了是死代码（ADR-106）。

**计时器与导航栏的间距靠运行时测量**

插件不假设宿主外壳有多高：它用几何判据（宽度 ≥ 视口 55%、顶边贴近顶端、
高度小于半屏、有子节点）找出「最上方的通栏容器」，取其底边 + 12px 写入
`--ig-safe-top`，HUD 只读这一个 CSS 变量。这样宿主改类名、换布局、
用户放大字体都不会导致遮挡。找不到候选时退回 52px（标题行常见高度 + 一点余量）。

测量在首次渲染、窗口尺寸变化、DOM 结构变化（宿主异步渲染外壳）时重跑，
合并到下一帧执行，不会在连续事件里把测量打爆。

代价：首次渲染时如果宿主外壳还没挂载，会先用兜底值、下一帧再校正 ——
理论上有一帧的偏移，肉眼不可见。

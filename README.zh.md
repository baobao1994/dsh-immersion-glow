# 沉浸觉察（dsh-immersion-glow）

DSH 会话内的静默助手。**你发起询问之后**，界面右上角才会常驻一行读数：现在在用哪个模型、
已经跑了多久。到阈值时提醒你回看，并让你记下「这次到底达到了吗」以及哪个模型顺手。

**零网络。数据不出本机。**

[English](README.md) · [已知限制](docs/known-limitations.md) · [决策记录](docs/ADR.md)

---

## 安装

```sh
D="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
"$D" plugin --profile desktop add /absolute/path/to/dsh-immersion-glow
```

**然后完全退出并重开 DSH。** 只刷新页面不够 —— 新 bundle 是结构性变更，不是配置热加载。

卸载：

```sh
"$D" plugin --profile desktop remove dsh-immersion-glow
```

## 它做什么

**发起之前什么都不做。** 本次会话没有真正发出过请求之前，右上角不出现任何东西。开一个会话、
翻一翻、想一想 —— 角落是干净的。把阈值设成空也同样不显示：**你设的阈值就是开关**。

**是读数，不是装饰。** 标题栏下方一个小圆环：环表示「离下一次该歇了还有多远」，中心是
模型的耗时，右侧是当前模型名。点开是明细：各模型占比条、模型耗时与工具耗时的对照、
以及每个模型一行（轮次、步数、你的历史评分与备注）。不抢焦点、不发声。

位置是**量出来**的（导航栏底边 + 12px），不是写死的 —— 所以换窗口宽度、
换字体、宿主改版都不会压到右上角那排按钮上。

**它知道每一段是哪个模型跑的。** 每次模型回复都用宿主自己的口径计时
（`step/start` → 消息完成），并归到真正产出它的那个模型上。session 中途换模型，占比跟着变。

**到阈值时，圆环自己开口。** 净活跃时间到 20 / 40 / 60 分钟时，圆环转成琥珀色、
冒出一行提示、跑 60 秒倒计时。**是同一个组件换个状态，不是又来一张卡。**
错过了就持续琥珀色 + 一个待读点。点它展开明细；这次任务可以收藏成记录卡。

**说说它达到了没有。** 记录卡只问一件事 —— 达到了吗：**达到了 / 基本达到 / 没达到**。
三档而不是勾选框，因为「基本做完、有点返工」才是最常见的诚实回答，boolean 会把它压扁。
你的回答会进入汇总里的达成率。

**记下哪个模型顺手。** 每个模型可以留一个五档评价（差 → 极其顺手）加一句备注。
**不会替你下结论** —— 见下。

**一切都在本机。** 设置、记录、评价、汇总都在一个 `localStorage` 键里（`immersion-glow.v1`）。
没有请求、没有遥测、没有账号。

## 它不做什么

**不替你评判模型。** 汇总里给的是客观指标 —— 耗时、首字延迟、解码速度、轮次。
这些就是宿主能测到的全部，**没有任何质量信号**，所以自动给出「哪个模型写代码更强」
只能是编的。面板把证据和你的评价并排放，结论留给你自己下。

完整清单见 [已知限制](docs/known-limitations.md)。

## 它读什么

这一版变过，所以写明白：

- **结构信息**：轮次与步骤边界、模型与提供方 id、token 数。
- **你第一条消息的第一句**，截断到 60 字，用作任务名，好让你过几天还认得出这次任务。
  除此之外**不读任何消息内容** —— 不读你的后续提问、不读模型输出、不读工具参数。

上一版的承诺是「绝不触碰正文」。要拿到有意义的任务名就必须读那一行，所以现在的承诺是
**更窄但明确**，而不是绝对的。

## 设置

`设置 → 通用` 下有一行：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用 | 开 | 总开关 |
| 触发阈值 | `20, 40, 60` | 逗号分隔，严格递增，1–6 个。**留空则完全不显示读数。** |
| 空闲冻结 | 3 分 | 超过这段时间没有操作就不再累加 |
| 右上角读数 | 开 | 常驻那一行与它的明细面板 |
| — | — | 收藏 / 汇总按钮、「已提醒 N 次 · 你打开了 M 次」、**复制统计**、**清除数据** |

## 开发

```sh
npm run build    # 把 src/client/*.js 内联进 lib/client.js
npm test         # 135 项测试：计时、指标、状态、模型归属、数据通路、产物契约
npm run verify   # 清单、patch、locale、零网络、require 白名单、沙箱
npm run check    # 以上全部
```

源码在 `src/client/*.js`，是**没有 import 的普通 JS** —— 各模块共享一个闭包，由
`tools/build-client.mjs` 按固定顺序内联。这是刻意的：DSH 的浏览器插件协议只要求
`window.__ModuleLoader__.load({ id, factory })`，且 `factory(require)` **只收一个参数**
（不是 CommonJS 的三个），手写产物在本机已有生产验证（见 `dsh-trae-checkin`）。
换来零依赖工具链，产物可读可 diff，测试还能直接求值源文件。

新增模块必须在 `tools/build-client.mjs` 的 `MODULES` 里登记，忘了 `npm run verify` 会失败。

### 逐模型耗时是怎么算出来的

宿主没有提供「按模型拆分耗时」的投影，所以这份数据是从 chat 快照推导的：每个 assistant 节点
就是一次模型调用，按 `completedTime - stepStartTime` 计时，再通过 `trajectory` 投影里的
`providerMetadata` 归到具体模型。该投影不可用时退回「当前模型」，并在界面上标明这是近似值 ——
**不猜**。

架构说明（含三处为让插件能加载而不得不做的实现层修正）见 [docs/ADR.md](docs/ADR.md)。
